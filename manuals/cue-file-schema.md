# NocturNation cue file schema

> Canonical reference for the `.cues` file format. Every directive, every cue-line keyword, every FX command name. Authoring tools must not invent new directives unilaterally — propose, settle, document here, then implement.

**Schema version**: 1
**Last updated**: 2026-06-26 (Epic 14 B0)
**Scope**: Music orchestrator (`nowplaying-orchestrator.py`) cue files under `Docs/songs/*.cues`. Parser lives at `Docs/tools/nocturnation_orchestrator/cues.py`.

---

## Overview

A cue file is a plain-text timeline that drives lighting + display effects in sync with a music track. The orchestrator matches a now-playing track (artist + title) to a cue file via a three-tier matcher, then walks the file in time with the music player's playhead. Each line is either a header directive, a comment, an empty line, or a timed cue.

**Design pillars**:

- **Plain text**, human-authorable in any editor.
- **One concept per line.** Easy to grep, easy to diff, easy to comment out.
- **Source-agnostic at runtime**: the orchestrator drives whatever DMX / Art-Net / USB-CDC target is wired up. Cue file authors don't need to know the wire layer.
- **Forwards-compatible**: unknown directives at the parser layer are an error today, but the schema reserves room for future Epic-introduced fields via `@analysis_version`.
- **Lyric-first authoring** (Epic 14): the canonical first-pass cue file is generated by `cues_from_lyrics.py` from lrclib.net synced lyrics, then optionally enriched by `audio_enrich_cues.py` with librosa MIR data. Either is a valid product.

## File structure

```
# comment lines start with # (full-line) or appear after content
# blank lines are ignored
@directive_name <args>      # zero or more header directives, any order
<MM:SS[.f]>  <cue_kind>     # zero or more timed cues, in time order
                            # (parser doesn't enforce order but
                            # walkers do; out-of-order cues fire late)
```

Files are typically organised:

```
# comment block: provenance, authoring notes
@artist     ...
@title      ...
@bpm        ...
@default_fx ...
@offset     ...
@section    ...             # Epic 14 - one per song section
@section    ...
@analysis_synced ...        # Epic 14 - tool stamp

00:02   HeaderText: Coldplay
00:02   BodyText:   Higher Power
00:11   sparkle_on_beat colour=#ff8800 prob=80
01:05   stop
...
```

## Cue-line syntax

```
<time>  <kind>  [args...]
```

| Field | Format | Notes |
|---|---|---|
| `<time>` | `MM:SS` or `MM:SS.f` | Minutes:seconds with optional fractional seconds (e.g. `01:23.500`). Absolute from track start. |
| `<kind>` | string | FX name, or one of the reserved keywords (`HeaderText:`, `BodyText:`, `clearscreen`, `bpm`, `stop`). |
| `[args...]` | space-separated tokens | Keyword args (`prob=80 colour=#ff8800`) or positional, depending on the kind. |

Time can use any whitespace between fields. Trailing comments (after `#` on a content line) are NOT currently supported by the parser — comments are full-line only.

## Header directives

### `@artist <free text>`
**Required.** Used by the orchestrator's three-tier matcher to identify the track. Joins all tokens after `@artist` with single spaces.

```
@artist     Coldplay
@artist     coldplay, BTS    # commas allowed; matched case-insensitively
```

### `@title <free text>`
**Required.** Track title; matcher joins tokens. Case-insensitive match.

```
@title      Higher Power
@title      My Universe
```

### `@bpm <N>`
**Required for tempo-aware FX** (`pulse_per_bar`, `sparkle_on_beat`, etc.). Integer beats-per-minute. Falls back to a tempo-agnostic default if unset, but FX that need a beat clock will misbehave.

```
@bpm        178
```

Mid-track BPM changes use the `bpm` cue-line keyword (see below).

### `@default_fx <fx_name> [args...]`
**Optional.** FX that runs when no other cue is active. Author typically picks `quiet_wash` with a subdued colour. Runs from track start until the first explicit FX cue, then resumes after each `stop`.

```
@default_fx quiet_wash 20 40 80         # subtle blue wash
```

The FX name is matched against the FX registry (see "FX commands" below); unknown names fail at parse time.

### `@offset <seconds>`
**Optional.** Float (positive or negative). Whole-file time shift applied to every cue + lyric at parse time. Positive offsets DELAY the cue file (use when the album has silence padding before audible content); negative offsets ADVANCE (rare — audio was authored against a longer intro than the playing copy).

```
@offset     0.085           # advance everything by 85 ms
@offset     -1.2            # ALL cues fire 1.2 s earlier than written
```

Per-player playhead-latency tuning lives here (Epic 14 B5).

### `@ShowSongInfo [true|false|on|off|1|0]`
**Optional.** Epic 13 display directive. When enabled, the orchestrator emits a `TEXT_DISPLAY` "now playing" card at track start with `HeaderText` = artist, `BodyText` = title. Bare directive = `true`.

```
@ShowSongInfo
@ShowSongInfo true
@ShowSongInfo false
```

### `@ShowBitmap [true|false|...]`
**Optional.** Epic 13 display directive. Reserved for a future "auto-load a track-keyed bitmap" feature; currently parsed but a no-op. Same boolean format as `@ShowSongInfo`.

### `@section <name> <start_ts> <end_ts> [tempo=<bpm>] [loudness=<dB>] [key=<name>] [mode=<m|M>]`
**Optional. New in Epic 14 (B2).** Marks one acoustic section of the track. Low cardinality (~10-15 per song). Sourced from librosa MIR; names are **author-supplied** (the tool emits `section1, section2, ...`; the author renames to `verse1`, `chorus1`, etc.).

```
@section intro      0:00.0   0:11.5   tempo=178.0  loudness=-14.2
@section verse1     0:11.5   0:35.0   tempo=178.0  loudness=-10.7
@section chorus1    0:35.0   0:55.7   tempo=178.0  loudness= -7.3
```

Boundary timestamps use the same `MM:SS.f` format as cue lines.

Reserved for future FX cue extensions like `@during <section_name> <fx>` (Epic 14 B7). Currently captured; not yet consumed by the orchestrator.

### `@duration <m:ss.s>`
**Optional. New in Epic 14 (B2).** Track duration. Runtime sanity check: if the player reports a length different from this, the master differs and the orchestrator can fail loud rather than playing the wrong cues.

```
@duration   3:31.5
```

### `@key <name>` + `@mode <major|minor>`
**Optional. New in Epic 14 (B2).** Spotify-style musical key + mode. e.g. `@key A#`, `@key Cm`. Reserved for future "auto-palette from key" feature; captured now so the data is there.

```
@key        A#
@mode       major
```

### `@analysis_synced <ISO-8601-timestamp>`
**Optional. New in Epic 14 (B2).** When the cue file was last MIR-enriched by `audio_enrich_cues.py`. Detects staleness if the audio file changes (different master).

```
@analysis_synced 2026-06-26T18:14:00Z
```

### `@analysis_version <int>`
**Optional. New in Epic 14 (B2).** Schema version when the file was last enriched. Future format migrations key off this. Current value: `1`.

```
@analysis_version 1
```

### `@analysis_tool <librosa>`
**Optional. New in Epic 14 (B2).** Which MIR tool produced the analysis. Currently always `librosa`. Field exists for future-proofing.

```
@analysis_tool librosa
```

### `@during <section_name> <fx_kind> [args...]`
**Optional. New in Epic 14 (B7).** Expands at parse time into a real cue at the named section's `start_ms`. Lets the author think in sections rather than timestamps. The referenced section must be declared via `@section` somewhere in the same file; ordering doesn't matter (resolution happens after all directives are parsed).

```
@section verse1   0:11.50  0:35.00
@section chorus1  0:35.00  0:55.70

@during verse1   quiet_wash 80 40 20
@during chorus1  sparkle_on_beat 255 100 50 80 0
```

The above is equivalent to writing:
```
00:11.50  quiet_wash 80 40 20
00:35.00  sparkle_on_beat 255 100 50 80 0
```

Multiple `@during` directives can target the same section — they all expand. Unknown section names emit a warning to stderr but don't fail the parse (so a typo doesn't kill the whole show).

Doesn't auto-cancel at the section's `end_ms` — the FX runs until the next cue replaces it (just like any other cue). Add an explicit `stop` cue or another `@during` if you want a hard cutoff.

### `@palette <name> <#RRGGBB>[,<#RRGGBB>...]`
**Optional. New in Epic 14 (B7).** Declares a named colour palette. Captured into `CueFile.palettes` for reference; **no automatic expansion in body cue arguments yet** (deferred to a future per-FX colour-arg pass). Useful for documenting brand palettes per stage / artist alongside the actual FX cues:

```
@palette stage_d   #FF0000,#FF8800,#FFFF00
@palette artist_x  #00AAFF, #0044FF, #8800FF
```

Spaces after the comma separators are tolerated. The leading `#` on each hex value is optional (`FF0000` works the same as `#FF0000`). Malformed entries are silently dropped (one typo doesn't break the palette). Last `@palette` with the same name wins on redefinition.

## Cue-line kinds

### `<time>  HeaderText: <text>`
Epic 13. Display-content cue. Updates the header (top) text on Lume LCDs. Sticky — persists until cleared or replaced. Empty text after the colon clears the header.

```
00:02   HeaderText: Coldplay
00:11   HeaderText:                       # clears the header
```

### `<time>  BodyText: <text>`
Epic 13. Display-content cue. Updates the body text. Same sticky / clear semantics as `HeaderText`.

```
00:11   BodyText: I'm so happy that I'm alive
00:35   BodyText: You've got a higher power
```

Non-Latin scripts (Hangul, kana, kanji, Cyrillic, etc.) render as missing-glyph boxes on the Tildagon. Romanise in the cue file. See [[tildagon-font-latin-only]] in project memory.

### `<time>  clearscreen`
Epic 13. Clears both `HeaderText` and `BodyText`. No arguments.

```
03:25   clearscreen
```

### `<time>  bpm <N>`
**Mid-track tempo change.** Updates the orchestrator's beat clock from this cue's time onwards. Used for tracks that shift tempo mid-song (a bridge at a different BPM, a half-time drop, etc.).

```
01:45   bpm 89                            # half-time bridge
02:20   bpm 178                           # back to the main tempo
```

### `<time>  stop`
**Cancels the active FX.** Implemented as a cue to the `blackout` FX (special id 0 in the registry). Resumes `@default_fx` afterwards if set; else darkness.

```
01:05   stop
```

### `<time>  <fx_name> [arg1=val1] [arg2=val2] ...`
**FX trigger.** Looks up `<fx_name>` in the FX registry, instantiates with the given args, and pushes onto the active-FX stack. New cues supersede previous ones until `stop` or another cue fires.

Argument syntax:
- `key=value` (kwargs)
- positional args (fewer common; FX-class-dependent)
- Numeric values: integers or floats
- Colours: `#rrggbb` hex or `r,g,b` decimal triple (FX-class-dependent)
- Booleans: `true` / `false` / `on` / `off` / `1` / `0`

See the FX command reference below for per-FX argument lists.

## FX commands

Eleven FX shipped at Epic 14 B0 time. The FX library lives at `Docs/tools/nocturnation_orchestrator/fx/library/`; each FX is a Python class with declared parameters. Reference here is summary-only; the per-FX docstring is authoritative.

| Name | id range | What it does | Typical args |
|---|---|---|---|
| `blackout` | 0 | All channels to zero. Internal — fires via `stop` cue, not authored directly. | none |
| `quiet_wash` | 1-10 | Steady-state low-intensity wash colour. Author's go-to ambient / verse FX. | colour (RGB), intensity |
| `drift_wash` | 1-10 | Wash with slow colour cycling between two anchors. | colour_a, colour_b, cycle_ms |
| `fade_to_black` | 1-10 | Time-linear fade from the current wash to zero. Track-outro use. | duration_ms |
| `pulse` | 11-20 | One-shot pulse on every detected beat (orchestrator-side beat clock from `@bpm`). | colour, attack, sustain, release, chance |
| `pulse_per_bar` | 11-20 | One pulse per bar (every N beats, where N = time signature). Sparser than `pulse`. | colour, attack, sustain, release |
| `sparkle_on_beat` | 11-20 | Per-pixel CHANCE-rolled sparkles on the beat. Most-used FX for energetic sections. | colour, prob (0-100), group_size |
| `wash_with_sparkle` | 11-20 | Combines `quiet_wash` (under) + `sparkle_on_beat` (over). Single cue = both layers. | wash_colour, sparkle_colour, prob |
| `linear_buildup` | 21-30 | Intensity ramp from 0 to full over `duration_ms`. Build-toward-the-drop FX. | colour, duration_ms |
| `group_cascade` | 31-40 | Sweeps a colour across Lume groups in order (group 1, then group 2, ...). | colour, sweep_ms |
| `strobe_burst` | 31-40 | Brief high-rate flash. Use sparingly + at low intensity (Harding-safe cap is < 5 Hz on the wire). | colour, rate_hz, duration_ms |

Detailed parameter specs (defaults, ranges, units) are in each FX class's docstring. A "cue-commands.md" deep-dive lives at Epic 14 B7.

## Sidecar JSON convention (Epic 14 B2)

When `audio_enrich_cues.py` runs, it writes a sidecar alongside the cue file:

```
Docs/songs/
  coldplay-higher-power.cues                  ← human-edited, in git
  coldplay-higher-power.cues.analysis.json    ← librosa dump, gitignored
```

The `.cues.analysis.json` contains the librosa output: tempo, beats array (~600 entries), onsets, section boundaries with confidence scores, chroma summary for key estimation. Gitignored: recoverable by re-running enrichment.

**The orchestrator never reads the sidecar at runtime.** It's authoring-tool-side only. Cue files compile to absolute timestamps; everything the orchestrator needs is in the `.cues` file.

```jsonc
{
  "tempo": 178.026,
  "time_sig": 4,
  "key": "A#",
  "mode": "major",
  "duration_s": 211.5,
  "beats": [0.024, 0.361, 0.698, 1.035, ...],     // seconds
  "onsets": [0.024, 0.085, 0.361, ...],
  "sections": [
    {"start": 0.0,   "end": 11.5, "tempo": 178.0, "loudness_db": -14.2},
    {"start": 11.5,  "end": 35.0, "tempo": 178.0, "loudness_db": -10.7},
    ...
  ],
  "chroma_summary": [0.12, 0.08, 0.34, ...],      // 12-bin pitch class energy
  "analysis_tool": "librosa",
  "librosa_version": "0.10.2",
  "synced": "2026-06-26T18:14:00Z"
}
```

Field shapes are stable across Epic 14 B2; future schema versions will key off `analysis_version` in the cue file header.

## Versioning + back-compat

- **Pre-Epic-14 cue files** (no `@analysis_*` directives, no `@section`) remain valid. The Epic 14 directives are additive.
- **Forwards-compat** is the orchestrator's responsibility: an `.cues` file authored under a future `@analysis_version > 1` should ideally parse leniently (ignore unknown directives + warn) rather than reject. (Current parser rejects unknown `@directive`s; this will change as B7 lands.)
- **Sidecar JSON shape changes** key off `analysis_version` in the cue file header. The librosa tool ships a single shape per major version.

## Worked example (post Epic 14 B2)

```
# coldplay-higher-power.cues
# Authored via Epic 14 workflow: cues_from_lyrics + audio_enrich_cues --seed --snap.
# Audio source: iTunes Store purchase 2026-06-26.

@artist     Coldplay
@title      Higher Power
@bpm        178
@time_sig   4
@key        A#
@mode       major
@duration   3:31.5
@default_fx quiet_wash 20 40 80
@offset     0.0

@analysis_synced  2026-06-26T18:14:00Z
@analysis_version 1
@analysis_tool    librosa

@section intro      0:00.0   0:11.5   tempo=178.0  loudness=-14.2
@section verse1     0:11.5   0:35.0   tempo=178.0  loudness=-10.7
@section chorus1    0:35.0   0:55.7   tempo=178.0  loudness=-7.3
@section verse2     0:55.7   1:19.2   tempo=178.0  loudness=-10.4
@section chorus2    1:19.2   1:39.9   tempo=178.0  loudness=-7.1
@section bridge     1:39.9   2:14.6   tempo=178.0  loudness=-9.8
@section chorus3    2:14.6   2:58.0   tempo=178.0  loudness=-6.9
@section outro      2:58.0   3:31.5   tempo=178.0  loudness=-12.4

# --- intro ---
00:02   HeaderText: Coldplay
00:02   BodyText:   Higher Power

# --- verse 1 ---
00:11   BodyText: I'm so happy that I'm alive
00:35   sparkle_on_beat colour=#ff8800 prob=60                  # seed

# --- chorus 1 ---
00:35   BodyText: You've got a higher power
00:35   wash_with_sparkle wash_colour=#ff4400 sparkle_colour=#ffaa00 prob=85   # seed

# ... etc.

03:25   clearscreen
03:30   stop
```

## Open schema questions

Captured here for future iteration. None block tooling work in Epic 14.

- **Lenient parsing of unknown directives**: should the orchestrator warn + ignore unknown `@directives`, or hard-fail (current behaviour)? Lean toward lenient with a warning as schema evolves. Decision in Epic 14 B7.
- **Per-section FX block syntax** (`@during chorus1 { ... }` or similar): the section directive is captured but not yet consumed by FX. B7.
- **Inline comments**: should the parser support trailing `# ...` on cue lines, not just full-line comments? Mildly useful for FX seed tags. B7.
- **Palette declarations** (`@palette stage_d #ff0000,#ff8800,#ffff00`): named colour lists referenced by name in body cues. B7.
